# 相机桥接使用说明（ASC60C → lerobot）

> 面向新手。真机采集前通读一遍，按顺序执行即可。
> 更新日期：2026-10-03

## 一、这套东西是干嘛的

安思疆 ASC60C 是 ROS2 SDK 相机：画面通过 ROS2 话题 `/ascamera/camera_publisher/rgb0/image`（bgr8, 640×480）输出，**不是** UVC 免驱摄像头，lerobot 的 opencv 相机读不了。

所以用 **v4l2loopback** 造一个虚拟的 `/dev/video10`：

```
ASC60C → ros2 launch ascamera → RGB 话题 ──► ros2_camera_bridge.py ──► /dev/video10 (虚拟相机) ──► lerobot opencv 相机
```

lerobot 侧就把 `/dev/video10` 当成一个普通 USB 摄像头读，不用改 lerobot 的任何采集逻辑。

## 二、已完成的准备工作（本机配置记录，供参照）

| 项 | 内容 | 位置 |
|----|------|------|
| v4l2loopback 安装 | dkms 模块 0.12.7 + 两处内核补丁（见下方说明） | `/lib/modules/6.8.0-138-generic/updates/dkms/v4l2loopback.ko` |
| 开机自动加载 | 每次开机自动 `modprobe v4l2loopback` 并带正确参数 | `/etc/modules-load.d/v4l2loopback.conf` |
| 模块参数 | `devices=1 video_nr=10 card_label="ASC60C_RGB" exclusive_caps=1` | `/etc/modprobe.d/v4l2loopback.conf` |
| 设备权限 | 普通用户可读写（0666），按设备名 `ASC60C_RGB` 匹配 | `/etc/udev/rules.d/60-v4l2loopback.rules` |
| 桥接脚本 | ROS2 话题 → /dev/video10 | `~/so101_hardware/ros2_camera_bridge.py` |
| lerobot 一行补丁 | opencv 相机优先用 V4L2 后端（见「常见坑 4」） | `~/wallx-workspace/wall-x/lerobot/src/lerobot/cameras/opencv/camera_opencv.py` |

**v4l2loopback 两个内核补丁是什么、为什么：**

1. `strlcpy → strscpy`：本机内核 6.8 移除了 `strlcpy`，原版 0.12.7 编译不过。
2. `capture_param->capability = V4L2_CAP_TIMEPERFRAME`：OpenCV 5.0 在设置帧率前会检查这个能力位，v4l2loopback 默认不报，导致 lerobot 校验 fps 时报错。

> ⚠️ 如果哪天 `sudo apt upgrade` 升级了 `v4l2loopback-dkms` 包，这两个补丁会被覆盖，需要重新打（命令见「附录 A」）。

## 三、真机采集启动顺序（照做即可）

```bash
# ① 插上相机，确认识别
lsusb | grep 3482          # 应看到 3482:6723 (NOVATEK ASJ ZNX_NVT)

# ② 加载虚拟相机（已配开机自动加载；手动加载只需一次）
sudo modprobe v4l2loopback
ls -l /dev/video10         # 应存在，权限 crw-rw-rw-

# ③ 启动相机 ROS2 节点（新开一个终端）
cd ~/ascamera_ws
source /opt/ros/humble/setup.bash
# <ASC60C-SDK路径> = ASC60C SDK 源码目录（含 linux_ros/ 子目录），按本机实际解压位置替换：
export LD_LIBRARY_PATH=<ASC60C-SDK路径>/linux_ros/ros2/ascamera/libs/lib/x86_64-linux-gnu:$LD_LIBRARY_PATH
source ~/ascamera_ws/install/setup.bash
ros2 launch ascamera ascamera.launch.py

# ④ 启动桥接（再开一个终端）
source /opt/ros/humble/setup.bash
python3 ~/so101_hardware/ros2_camera_bridge.py

# ⑤ 启动 lerobot 数据采集（lerobot conda 环境；完整多相机语法见 真机录制checklist.md）
conda activate lerobot
python -m lerobot.record \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyUSB0 \
  --robot.id=so101 \
  --robot.cameras='{
    "global":   {"type": "opencv", "index_or_path": "/dev/video10", "width": 640, "height": 480, "fps": 30},
    "wrist":    {"type": "opencv", "index_or_path": 1, "width": 480, "height": 480, "fps": 30},
    "panorama": {"type": "opencv", "index_or_path": 2, "width": 640, "height": 480, "fps": 30}
  }' \
  --teleop.type=so101_leader --teleop.port=/dev/ttyUSB1 --teleop.id=leader \
  --dataset.repo_id=your_dataset_name \
  --dataset.num_episodes=10 --dataset.fps=30 \
  --dataset.single_task="..."
```

> ASC60C 桥接出来的这一路就是 `global`（640×480）；其余相机 index 按 `find_cameras` 实际结果改。

> **顺序很关键**：桥接（④）必须比 lerobot（⑤）先启动。`exclusive_caps=1` 的虚拟相机只有在"有写入者"时才向读取端报告"我是摄像头"；lerobot 先开的话会打不开设备。
> 桥接启动后即使相机还没出图，也会往 /dev/video10 写 "WAITING FOR CAMERA..." 占位帧，lerobot 不会卡死。

## 四、每一步的验证命令

```bash
# ① 相机识别
lsusb | grep 3482

# ③ ROS2 出图确认（帧率应稳定在 25~30）
ros2 topic list | grep ascamera
ros2 topic hz /ascamera/camera_publisher/rgb0/image

# ④ 桥接出图确认（两种方法任选）
# 方法 A：OpenCV 读一帧存图
python3 -c "
import cv2
cap = cv2.VideoCapture('/dev/video10', cv2.CAP_V4L2)
print('opened:', cap.isOpened(), 'size:', cap.get(cv2.CAP_PROP_FRAME_WIDTH), 'x', cap.get(cv2.CAP_PROP_FRAME_HEIGHT))
ret, frame = cap.read()
cv2.imwrite('/tmp/bridge_check.png', frame)
print('saved /tmp/bridge_check.png')"
# 打开 /tmp/bridge_check.png 看是不是相机画面

# 方法 B：v4l2-ctl 看设备状态
v4l2-ctl -d /dev/video10 --all | grep -E "Width|Pixel|Card"

# ⑤ lerobot 侧找相机（lerobot 环境里）
conda activate lerobot
python -m lerobot.find_cameras opencv     # 应列出 /dev/video10，默认 640x480@30

# 桥接脚本自己的统计（每 5 秒一行）：收到=ROS帧数，写入=写入设备帧数
# 如果「丢帧」持续>0，说明没有消费者在读 /dev/video10（lerobot 还没开）
```

**无相机自检**（相机没插时验证整条链路）：

```bash
# 终端 1：桥接写合成测试图（红色底 + 移动白条）
python3 ~/so101_hardware/ros2_camera_bridge.py --synthetic
# 终端 2：读回验证
python3 -c "
import cv2
cap = cv2.VideoCapture('/dev/video10', cv2.CAP_V4L2)
ret, frame = cap.read()
print('read:', ret, frame.shape, 'corner BGR:', frame[5,5].tolist(), '(应为 [0,0,255] 红)')"
```

## 五、常见坑

1. **`ros2 launch ascamera` 启动即崩 `libAngstrongCameraSdk.so not found`**
   没有 `export LD_LIBRARY_PATH=<ASC60C-SDK路径>/linux_ros/ros2/ascamera/libs/lib/x86_64-linux-gnu:$LD_LIBRARY_PATH`。必须在 launch 的同一个终端里 export。

2. **相机不出图 / 报 `cannot find config file`**
   `ascamera.launch.py` 里 `confiPath` 是硬编码 dict，必须指向绝对路径：
   `<ASC60C-SDK路径>/linux_ros/ros2/ascamera/configurationfiles`（详见 ASC60C SDK 附带的官方调用指南第五节）。

3. **权限 denied**
   - ASC60C 本体：`/etc/udev/rules.d/angstrong-camera.rules` 已配 0666，插上就有权限。
   - 虚拟相机：`/etc/udev/rules.d/60-v4l2loopback.rules` 已按设备名 `ASC60C_RGB` 配 0666。手动 modprobe 后权限不对就执行：
     `sudo udevadm control --reload-rules && sudo udevadm trigger`

4. **lerobot 报 `failed to set fps=30` / `failed to set capture_width`（OpenCV 5.0 特有）**
   本机 OpenCV 5.0 的 CAP_ANY 后端会把 /dev/video* 交给 FFMPEG 后端，而 FFMPEG 后端不支持在 V4L2 设备上设置 fps/宽高，lerobot 的校验就会抛 RuntimeError。
   已对 lerobot 打了一行补丁：`camera_opencv.py` 的 `connect()` 里对 `/dev/video*` 路径和整数 index **优先用 cv2.CAP_V4L2 后端**（视频文件仍走原逻辑）。
   **如果哪天重装/更新了 lerobot 源码，这个补丁会丢**，症状就是上面的报错。恢复方法见「附录 B」。

5. **`index_or_path` 用 10 还是 "/dev/video10"？**
   推荐 `"/dev/video10"`。OpenCV 的整数 index 是"它自己枚举出来的设备列表序号"，不是 /dev/videoN 的编号——本机内置摄像头占了 video0/video1，纯用 index 时容易对不上号。路径字符串没有歧义（实测 10 在打了附录 B 补丁后也能用，但路径最稳）。

6. **lerobot 打开 /dev/video10 失败 `ConnectionError`**
   几乎都是顺序问题：桥接脚本没在运行。`exclusive_caps=1` 的虚拟相机没有写入者时对外表现为"输出设备"而不是"摄像头"。先启动桥接再启动 lerobot。

7. **像素格式不匹配 / 画面颜色不对**
   桥接固定写 `RGB3`（V4L2_PIX_FMT_RGB24）640×480。不要用别的工具（ffmpeg 等）同时往 /dev/video10 写别的格式；两个写入者会互相覆盖格式协商。

8. **为什么只有 RGB，没有深度？**
   lerobot 0.3.4 的 opencv 相机本来就是 rgb-only 单流（0.3.4 里不存在 0.6.1 的 `use_depth` 参数，用 `type: opencv` 就是纯 RGB），wall-oss 微调也只用 RGB，所以桥接只做 RGB 这一路。ASC60C 的深度话题 `/ascamera/camera_publisher/depth0/image_raw`（16UC1, 毫米）相机节点照常发，以后要用的话参考 ASC60C SDK 示例脚本 `save_camera_frame.py` 的读取写法；要给深度也开一路虚拟相机需在 modprobe 参数里改 `devices=2` 并扩展桥接脚本。

## 附录 A：重打 v4l2loopback 内核补丁（仅 apt 升级该包后需要）

```bash
sudo sed -i 's/strlcpy(/strscpy(/g' /usr/src/v4l2loopback-0.12.7/v4l2loopback.c
sudo sed -i 's/capture_param->capability = 0;/capture_param->capability = V4L2_CAP_TIMEPERFRAME;/' /usr/src/v4l2loopback-0.12.7/v4l2loopback.c
sudo dkms remove v4l2loopback/0.12.7 --all
sudo dkms add v4l2loopback/0.12.7
sudo dkms build v4l2loopback/0.12.7
sudo dkms install v4l2loopback/0.12.7
sudo modprobe v4l2loopback     # 或 sudo rmmod v4l2loopback && sudo modprobe v4l2loopback
```

## 附录 B：恢复 lerobot 的 V4L2 后端补丁（重装 lerobot 源码后需要）

文件：`~/wallx-workspace/wall-x/lerobot/src/lerobot/cameras/opencv/camera_opencv.py`，`connect()` 方法内，
原代码是：

```python
self.videocapture = cv2.VideoCapture(self.index_or_path, self.backend)
```

改为：

```python
# 对 /dev/video* 路径和整数 index 优先用 V4L2 后端（OpenCV 5.0 的 FFMPEG 后端
# 不支持在 V4L2 设备上设置 fps/宽高，会导致 _configure_capture_settings 抛错）
is_v4l2_target = isinstance(self.index_or_path, int) or (
    isinstance(self.index_or_path, (str, Path))
    and str(self.index_or_path).startswith("/dev/video")
)
if is_v4l2_target:
    self.videocapture = cv2.VideoCapture(self.index_or_path, cv2.CAP_V4L2)
    if not self.videocapture.isOpened():
        self.videocapture.release()
        self.videocapture = cv2.VideoCapture(self.index_or_path, self.backend)
else:
    self.videocapture = cv2.VideoCapture(self.index_or_path, self.backend)
```
