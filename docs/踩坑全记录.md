# SO-ARM101 踩坑全记录（真机阶段避坑手册）

> 汇总：RL 仿真线（REWARD_ENV_FIXES.md 全部坑）+ 全局已知坑清单。
> 每条 = 描述 / 症状 / 根因 / 修法，新人照着能避坑。
> 第 2–4 节来自 mujoco_lerobot 仿真项目（wall-oss RL 线，见该项目仓库），
> 其余各节为本仓库真机 ACT 线；只关心真机 ACT 线可读第 1、5–8 节。

## 1. 方法论（最重要，先读）
1. **先 smoke 后长跑**：任何长跑前用 2 epochs 全链路（训练→保存→加载→推理→小评估）走通；
   长跑必须带中途 checkpoint。症状：数小时长跑训完崩在保存（真实发生两次）。修法：smoke 铁律。
2. **振荡=有 bug**：训练曲线锯齿/反复不是"等它收敛"，当 bug 查根因。
   症状：PPO fine-tune 5%↔17.5% 反复。根因：σ 比成功盆地宽 2.5 倍。修法：σ 强衰减到盆地以下。
3. **多方法同死→查共享环节**：五个学习模型都死在压紧→抬升，根因在共享的数据/评测口径
   （背时钟数据 + eval 提前 45 步闭合）。症状：换模型不换数据没用。
4. **不把方法问题定论成物理极限**：先穷尽实现/用法归因再谈天花板（本线即如此挖出 12+ bug）。
5. **拟合更好≠泛化更好**：MSE 降而成功率降 = 过拟合信号（图像 ACT：MSE 0.0018→0.0006，
   成功率 15.6%→3.1%）。

## 2. RL 环境与奖励线（12+ bug，全部有运行时证据）
1. **approach 奖励用错度量**：旧奖励 |ee−物块中心| 在正确位姿处仍非零 → 梯度持续把叉往物块里拉。
   修法：改"物块中心到捕获盒（叉体坐标系）距离"，正确位姿处为 0。
2. **onset 奖励设计缺陷**：touch/pinch 每次翻转都 +2/+3，success=0 的退化策略也能拿 mean_rew≈220。
   修法：episode 内锁存，各只给一次。
3. **成功奖励被 γ 折现**：+50 在 step~160 折到 ~10，退化策略回报反而更高。修法：+200，验证"退化策略回报 < 成功回报的一半"。
4. **训练分布≠评测分布**：训练 cube 固定 home、评测全区随机。修法：cube_xy_bounds 显式传全区范围（托盘环 rejection）。
5. **相机碰撞体缺失**：RL 场景副本的腕部相机 collision 没有 contype=0，随机动作 18/30 ep 撞桌。
   修法：加 contype/conaffinity=0（主场景本来就有）。
6. **成功 hold 判据 4 倍过严**：env 2.0s vs 采集侧 0.5s。修法：统一 15 步。
7. **max_episode_steps 截断**：成功需 ~270 步而默认 250 → 全部评测被截断在成功前（BC 0% 的元凶之一）。
   修法：400。
8. **_pinch 几何错误**：38/44 是 visual（contype=0 永不碰撞），真碰撞齿=37/39/45；旧实现 37 漏判。
   修法：grip_geoms={37,39,45}。
9. **SB3 LinearSchedule 分块塌缩**：分块 learn() 里 progress_remaining 塌到 0 → lr 恒为 end 值。
   修法：分块常数 lr（lambda 闭包）。
10. **gripper 二值分类头病理**：0/100 二值头离流形外推 −17/+101，接触闪烁即毁整集。
    修法：夹爪脚本化（contact/pinch/近锚点 3 行规则），策略只学 5 维臂。
11. **frozen z-score + 全区失败梯度**：PPO fine-tune 从 BC init 一更新就毁（4 组配置全锯齿）。
    修法：确定性专家或序列模型，别用局部梯度法硬调梳状奖励面。
12. **demo 边界检测对失败 ep 失效**：未抬升失败的 ep 结尾无 z-drop → ep 粘连（1420 步大 ep）、
    clock 腐败。修法：有 meta 时用 meta，边界检测仅兜底。
13. **qvel/cube_vel 混沌维**：PD 伺服速度尖峰（±36 rad/s）不可复现，进策略输入一步即离流形。
    修法：从输入剔除。
14. **anchor 特征不一致**：lookup 文件在采集后被改，2 格 demo 锚点与 env 提供值差 1.0 rad。
    修法：锚点表从 demo 录得值重建（多数决）。

## 3. 仿真物理线（抓取本身）
1. **wrist_roll 是甜点维度**：位置相关，钉死一个值丢 85% 区域；wr 是每格成败唯一翻转维度。
2. **桨板叉 V 槽只能兜/勾**：不能对夹（设计如此，别按夹爪思路写抓取）。
3. **抬升必须姿态相关**：叉轴朝方块侧倾 30-80°；竖直直线抬升 0/39 全失败。
4. **位置伺服是弹簧会泄力**：物块一让劲伺服就泄。修法：ctrl 压到限位外（−0.35）饱和恒压 3.35N·m。
5. **穿模根因=EE 趋近深度错误**：某 teleop 姿态 EE 在物块占位盒内、叉齿插进 28mm。
   修法：用捕获盒/捕获点约束趋近目标（grasp_offset≈0.028m）。
6. **开环 rollout ±2mm 敏感**：随机位置离格中心 >2mm 概率 97% → 固定轨迹策略必挂。
7. **每格稠密候选**：12 解族 × 28 档 wr 预解（lookup），端到端验证过才可用。

## 4. 数据/学习路线判定（实验 1/2/3 结论）
1. **开环序列=背时钟数据**：动作是 t 的函数不是状态的函数；策略变"时钟回放器"，
   pinch 闪烁一步即崩。修法：闭环专家（contact 触发压紧 + 高度伺服）采集；失败恢复段要保留。
2. **学习路线 mm 墙（六配置全证）**：MLP-BC 10.4% / DAgger 11.5% / ACT 15.6% / ACT+伺服 16.7% /
   PPO 锯齿 ≤17.5% / 多样性 ACT 3.1% / 图像 ACT 3.1%，全部 < 确定性专家 82.6%（演示格）。
3. **脚本化扰动≠遥操作多样性**：扰动变体数据拟合更好（MSE 减半）但泛化更差——多样性假设证伪；
   sherryxychen 90% 的关键是真遥操作。
4. **仿真渲染图不携带 mm 精度**：global 视图物块 15-24px，图像 ACT 3.1%；wrist 视图 700-1200px
   （但 wrist 变体训练未完成）。真机相机需近距视角、物块 ≥数百像素。
5. **确定性混合专家是唯一达标**：push-aware 接近段+开环验证尾部，演示格 82.6%；全区短板=离格位置
   （784 格仅 ~100 格端到端验证）。

## 5. wall-oss 环境与数据
1. **环境 pin 死**：transformers==5.2.0、tokenizers==0.22.2（拒 0.23.2）、lerobot vendored 0.3.4 用
   --no-deps（0.6.x 报 delta_timestamps 错）、numpy<2、pyarrow<23、numba<0.62、torchrun 启动
   （python 直跑会挂）。
2. **数据格式 v2.1 vs v3.0**：meta 结构、shape 重排、Arrow 元数据、episodes_stats 全不同，混用即崩。
3. **相机 key 不统一**：真机无 .rgb 后缀、仿真有；混训前必须 unify。
4. **dof_config key 命名**：不能含 relative/rotation/6D 子串（解析器保留字）。
5. **meta.camera_keys 与 config key_mappings.camera**：集合+顺序必须一致。
6. **单臂 10 维落在预训练左臂槽位**：padding 16 只对齐维度不对齐语义，注意行为偏差。
7. **LoRA 4 处改动**：use_lora 没接线 / 默认 target q_proj 不存在（是融合 QKV）/ 只冻 decoder /
   注入时机在权重加载前会静默丢权重——每处都要核对。
8. **4060 8GB 跑不动官方 bf16 推理栈**：显存不够，需量化/减配。
9. **LIBERO 相机键**：实际是 image/image2，不是 faceImg/rightImg。
10. **云端缺 torchdiffeq**：要提前补装。

## 6. 相机桥接
1. **ASC60C 非 UVC 直通**：走 ROS2 SDK（ros2 launch ascamera），LD_LIBRARY_PATH 必须 export。
2. **v4l2loopback 在 kernel 6.8 编译失败**：strlcpy→strscpy + CAP_TIMEPERFRAME 两补丁；
   apt 升级内核会覆盖，要重打。
3. **OpenCV 5.0 无 V4L2 写后端**：用裸 ioctl 写。
4. **lerobot camera_opencv.py 1 行补丁**（/dev/video* 优先 CAP_V4L2）：重装 lerobot 会丢。
5. **桥接先于 lerobot 启动**：exclusive_caps=1 抢独占。
6. **kernel 6.8 struct v4l2_format 布局变了**：union 8 字节对齐，自写 ioctl 要按新布局。

## 7. 舵机/真机
1. **HX 舵机按 sts3215 协议驱动**：型号号 777；connect(handshake=False) 跳过型号严格校验。
2. **gripper 电流减半补丁只在 SO101Follower.configure() 生效**：直接操作原始 bus 不会自动执行。
3. **设 ID 必须一个个接**：全串联会把多个舵机写成同一 ID。
4. **校准零点写进固件**：Present_Position = Actual − Homing_Offset；校准只改读数不改数据格式。
5. **主从臂各自 ID 1-6**：两个驱动模块、两个 USB 端口。
6. **Ubuntu 下舵机模块可能枚举成 ttyCH341USB0**（CH34x 芯片）而非 ttyACM0；装机先 ls /dev/tty*。
7. **采集命令 --teleop.id/--robot.id 必须与校准一致**：缺 id → None.json → 交互式校准阻塞 →
   homing offset 被写坏 = 脏数据。
8. **命令行尾 \ 后不能跟 # 注释**：bash 会截断命令。

## 8. 磁盘/环境
1. **磁盘挂载点迁移后软链失效**：/mnt/data → /media/<user>/E，软链要重指。
2. **CUDA torch 装法**：同版本号只把 +cpu 换 +cu126（低风险）；装完验证 CPU 采集路径不破坏 + 留回滚命令。
3. **4060 8GB 跑 MJX 会 OOM**：13 个 mesh 凸包碰撞中间量 3500 万元素；本机 CPU 16 核多进程更快。
