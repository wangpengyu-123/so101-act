## 2. 正确录制命令（贴全）

```bash
source ~/miniconda3/bin/activate lerobot

python -m lerobot.record \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM1 \
  --robot.id=my_awesome_follower_arm \
  --robot.cameras='{"global": {"type": "opencv", "index_or_path": "/dev/video10", "width": 640, "height": 480, "fps": 12}}' \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyACM0 \
  --teleop.id=my_awesome_leader_arm \
  --dataset.repo_id=<user>/so101_table_pick_place \
  --dataset.root=~/so101_walloss/so101_real_record \
  --dataset.fps=12 \
  --dataset.num_episodes=20 \
  --dataset.episode_time_s=600 \
  --dataset.reset_time_s=600 \
  --dataset.single_task="Grab the red block and place it on the target" \
  --dataset.push_to_hub=false
```

要点与坑（都已验证）：

- **端口不要写反**：主臂(握柄)=ttyACM0，从臂(执行)=ttyACM1。旧 checklist 写反了。
- **fps 12 两处都设**：相机 dict 里 `"fps": 12` + `--dataset.fps=12`。
- **`--dataset.repo_id` 必须带斜杠**（如 `<user>/xxx`）：`lerobot.record` 内部
  `sanity_check_dataset_name()` 会 `repo_id.split("/")` 解包成两部分，无斜杠直接 `ValueError`。
  前缀随意（仅作本地标识，`push_to_hub=false` 不会真上传）。
- **`--dataset.root` 必须是不存在的目录**：`LeRobotDataset.create` 用 `exist_ok=False`，
  目录已存在会报错。每批换新目录（如 `so101_real_record_batch1` / `_batch2` …）。
- **必须加 `--dataset.push_to_hub=false`**：默认是 `true`，录完会尝试推 HF Hub 报错。
- 可选参数：`--display_data=true`（开可视化窗口）。

### 2.1 手动确认（ENTER 控制）操作流程

已改 `~/wallx-workspace/wall-x/lerobot/src/lerobot/record.py`（本机 lerobot 0.3.4 源码），
每条 episode 不再依赖固定时长（20s 不够用），改为**终端按 ENTER 控制**（pynput 方向键在本机不可靠）：

1. **开录前**：终端出现 `Press ENTER to start recording episode N...` → 把物块摆到随机初始位、手臂握好初始位姿 → **按 ENTER** 才开始录这条。
2. **录制中**：任务完成（抓→放全程结束）→ **按 ENTER** 立即结束录制段（不再等固定时长）。
3. **复位段**：出现 `Reset the environment` → 把物块摆到**新的**随机初始位 → 摆好后**按 ENTER** 跳过剩余复位时间。
4. **兜底**：`episode_time_s=600` / `reset_time_s=600`，即使全程不按 ENTER，单段最多 600s 自动结束（不无限挂死）。
5. 原有 pynput 监听（RIGHT 提前结束 / LEFT 重录本条 / ESC 停止）**未改动**，能用就继续用。

已知坑（可接受）：
- **连按两次 ENTER**：第一下结束当前段、被 `enter_pressed()` 吃掉；第二下残留在 stdin 缓冲，
  会被下一条的 `input("Press ENTER...")` 直接吃掉 → **下一条不等确认直接开录**。按 ENTER 一下一下来。
- **ENTER 前误输入其它字符**（如 `ok` + ENTER）：整行被 `enter_pressed()` 吃掉但**不算**按 ENTER（不结束录制），
  字符也不会漏给下一个 `input()`。
- 必须**在真实终端里跑**（stdin 是 TTY），不要把 stdin 重定向成 `</dev/null` 或管道（`enter_pressed()` 对 EOF
  恒返回 True、`input()` 会直接 EOFError）。
- **相机读帧超时已修（两轮加码）**：`OpenCVCamera.async_read` 默认 `timeout_ms` 200 → 最终 **5000**
  （`camera_opencv.py:440`，docstring 同步）。
  - 第一轮 200→1000：ASC60C 帧间隔抖动实测最大 ~404ms，200ms 会误报
    `Timed out waiting for frame from camera ... after 200 ms`。
  - 第二轮 1000→5000：episode 2 又崩 `after 1000 ms`，但桥接统计显示崩溃期间 ROS2 帧持续到达（8fps 无断流）、
    桥接持续写 `/dev/video10`——**不是相机断流**，而是 lerobot 读线程 `_read_loop → read()`
    （阻塞式 DQBUF）偶发被 v4l2loopback/OpenCV 帧丢失卡住 1-2 秒。5000ms 对该卡顿有充足余量，
    且相机真断流时最多每条等 5s 报 TimeoutError，不会无限挂起。
  - 改完**重新跑录制命令**即可（上次崩溃留下的半初始化数据集目录已删，`--dataset.root` 可复用同一路径）。
- **崩溃时从臂冻结 1 秒是同一根因**：录制循环顺序是 camera read → motor read → leader read → send_action，
  相机读卡住时整个循环停摆、从臂收不到新指令 → 冻结。相机超时放宽后该现象随之缓解；
  录制时若发现从臂短暂停顿，先查相机读帧，不要怀疑舵机。
- **实际录制帧率只有 ~6-7fps，fps=12 只是名义值**：camera 实际 8fps + 每帧舵机读写耗时拖慢循环；
  `--dataset.fps=12` 只决定 busy_wait 的下限节奏（循环体耗时超过 1/12s 时 busy_wait 直接返回）。
  注意：lerobot 0.3.4 的 `add_frame` 存的是**名义时间戳**（`frame_index / fps`，均匀间隔），不是墙钟时间；
  这是 0.3.4 标准行为，wall-oss 加载器算 action chunk 时间增量只用 `fps`（`t/fps`），所以训练可用，
  不要因"没到 12fps"或"时间戳均匀"怀疑数据坏（verify 脚本 fps 项记 WARN 也是这个原因）。

## 3. 每 20 条批量 verify

录完一批（例如 20 条）后，在 lerobot 环境跑：

```bash
source ~/miniconda3/bin/activate lerobot
python ~/so101_walloss/verify_real_dataset.py --src ~/so101_walloss/so101_real_record
echo "exit=$?"    # 0 = 无 FAIL；非 0 = 有 FAIL，数据不可用，先修再训
```

脚本检查的 7 项（`~/so101_walloss/verify_real_dataset.py`）：

| # | 检查 | 通过/告警口径 |
|---|---|---|
| 1 | 基本统计 episodes/frames/fps | fps=12 会记 **WARN**（<30Hz 遥操作可接受），不是 FAIL |
| 2 | state/action 维度=6 + joint 顺序 | 顺序 = shoulder_pan→gripper；已兼容真机 `.pos` 后缀名 |
| 3 | 前 5 关节 [-100,100]、gripper [0,100] | 越界 FAIL；gripper 软容差带只记 INFO |
| 4 | 相邻帧瞬移（掉帧）检测 | 前 5 body 关节按 0.3 rad 逐关节阈值，超阈 WARN |
| 5 | 相机 key | 接受 `observation.images.global` 或 `.global.rgb`（单相机） |
| 6 | 数值分布 sanity + wrist_roll 甜点 | INFO/WARN |
| 7 | norm_stats 是否存在 | 新录数据缺 norm_stats 记 **WARN**（预期），训练前再生成 |

> 注：对真机数据，`fps=12` 的 WARN 和 `norm_stats 缺失` 的 WARN 都是**预期现象**，
> 只要「结论: 无 FAIL」即可。退出码 0 才表示可用。

## 4. camera key 统一（必做，用 unify_camera_keys.py）

**为什么必须做**：lerobot 0.3.4 直接录出的相机 key 是 `observation.images.global`（无 `.rgb`）；
而 `~/so101_walloss/config.yml` 的 `key_mappings.camera` 写的是
`observation.images.global.rgb`（带 `.rgb`，与仿真数据一致）。wall-oss 加载器
`_vision_preprocess()` 对数据集里**每一个** camera key 都去 `key_mappings.camera` 里查表，
查不到就 `KeyError`。所以要么统一数据 key，要么改 config。推荐统一数据（这样真机/仿真可混同训）。

**脚本**：`~/so101_walloss/unify_camera_keys.py`（改名 `observation.images.global` → `.global.rgb`，
会同步改 `meta/info.json` 的 features、`videos/chunk-*/<key>/` 目录名、
`meta/episodes_stats.jsonl` 的 stats key）。

**做法（推荐：输出到新目录，源数据不动）**：

```bash
source ~/miniconda3/bin/activate lerobot
python ~/so101_walloss/unify_camera_keys.py \
  --src ~/so101_walloss/so101_real_record \
  --dst ~/so101_walloss/so101_real_record_rgb \
  --verify
```

`--verify` 会用 lerobot 重新加载并打印 `meta.camera_keys = ['observation.images.global.rgb']`。
之后再对 `--dst` 目录跑一次 verify 确认：

```bash
python ~/so101_walloss/verify_real_dataset.py --src ~/so101_walloss/so101_real_record_rgb
```

备选（就地改，先自动备份）：`python ~/so101_walloss/unify_camera_keys.py --src <dir> --backup --verify`
（备份到 `<dir>_pre_unify_backup`）。
另一条路（不动数据、改 config）：把 `config.yml` 的 `key_mappings.camera` 改成
`observation.images.global: global_view`（去掉 `.rgb`），但这样就不能和仿真 `.rgb` 数据混训。

## 5. norm_stats 重算 + wall-oss config 指向

wall-oss 加载器强制要求 `norm_stats_path`，且必须和真实数据分布匹配（现有
`~/so101_walloss/norm_stats.json` 是仿真数据的，真机微调前要重算）。

```bash
source ~/miniconda3/bin/activate lerobot
python ~/so101_walloss/compute_norm_stats.py \
  --data_root ~/so101_walloss/so101_real_record_rgb \
  --output_path ~/so101_walloss/norm_stats.json
```

（等价替代：`verify_real_dataset.py --src <dir> --write-norm-stats <path>`，格式相同。）

然后改 `~/so101_walloss/config.yml` 两处，让训练指向真机数据：

```yaml
  lerobot_config:
    repo_id: so101_table_pick_place        # 保持不变（仅作 normalizer key / dataset_names）
    root: /path/to/so101_walloss/so101_real_record_rgb   # ← 改成统一后的真机数据目录
  ...
  norm_stats_path: /path/to/so101_walloss/norm_stats.json   # ← 改成刚重算的文件
```

## 6. 录制时固定注意事项

- **物块**：直径 3.6cm 红色物块（与仿真物块一致），初始位/目标位在机械臂可达区内随机，
  不要只放正前方一个固定点。
- **相机距离**：物块/桌面距相机约 **0.4m**，保证 640×480 里物块清晰且不被遮挡。
- **桌面**：**纯色桌面**（无花纹/反光/杂物），降低 VLM 视觉歧义。
- **动作**：遥操作动作**连贯、顺滑**，避免大幅突跳（verify 第 4 项瞬移检测会抓 0.3 rad 以上单帧跳变）；
  抓取和放置动作要完整覆盖「接近→抓取→搬运→放置→松开」全过程。
- **条间复位**：每条 episode 结束时把物块放回新的随机初始位（lerobot 会留 reset 时间）。
- **夹爪**：闭合夹取时让夹爪真正夹住（gripper 归一化接近 0），放置时松开到位（接近 100）。
